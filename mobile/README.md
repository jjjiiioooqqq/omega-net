# SoF-inity mobile app

React Native (Expo) app that configures and drives a SoF-inity speaker
array over Bluetooth Low Energy.

## Why the app streams parameters, not audio (read this first)

Classic Bluetooth audio (A2DP) is **stereo and point-to-point**: a phone
cannot stream N independent audio channels to N speakers. Pretending
otherwise would be folkloric. SoF-inity's transport design works within
what Bluetooth actually provides:

- **Program audio** reaches every speaker as one *shared* stream —
  LE Audio broadcast (Auracast), line-in, or the speakers' own Wi-Fi
  sync. All speakers hear the same audio.
- **Spatialization** is what the app computes and transmits: each
  speaker gets its *own* time-alignment delay, level trim, and a live
  stream of Q15 gain keyframes over BLE GATT. The speaker applies them
  to the shared audio locally. This is the spatiotemporal multiplexing
  schedule from `engint.spatial_audio`, delivered as data.

Bandwidth check: a gain keyframe is 13 bytes; at 50 Hz per speaker
that's 650 B/s per link — comfortably inside BLE throughput even for
an 8-speaker array. Clock alignment uses an NTP-style two-way exchange
per speaker (accuracy bounded by BLE link asymmetry; round-trip time
is reported so bad exchanges can be rejected — expect millisecond-class
sync, good enough for gain envelopes, not for phase-coherent
beamforming, which we therefore do not claim).

## Structure

- `core/` — `@sofinity/core`: pure TypeScript, no runtime dependencies.
  - DSP port of the Python engine (acoustic map, VBAP ring panner,
    Gerzon energy-vector metric, gain scheduler). The Python package
    in `src/engint/spatial_audio/` remains the reference; tests mirror
    each other.
  - BLE protocol codec. `engint/spatial_audio/ble_protocol.py` is the
    speaker-firmware reference implementation; both codecs are tested
    against the same committed golden vectors
    (`core/test/fixtures/protocol_vectors.json`, generated by the
    Python side) so they cannot drift apart silently.
- `app/` — the Expo app.
  - `src/ble/SpeakerLink.ts`: transport interface + mock array for
    development without hardware.
  - `src/ble/BlePlxLink.ts`: real BLE via `react-native-ble-plx`.
  - Screens: **Speakers** (scan/connect/clock-sync), **Layout** (enter
    measured positions; live acoustic map with per-speaker delay/trim),
    **Play** (apply alignment, stream a demo orbit schedule; shows the
    worst-case Gerzon localization error).

## GATT protocol (v1)

Service `50f1a5d0-0001-4e0b-bf3a-6f1c2d3e4a01`, little-endian frames:

| Frame | Type | Layout | Size |
|---|---|---|---|
| SET_ALIGNMENT | 0x01 | u32 delay_us, u16 gain_q15 | 7 B |
| GAIN_FRAME | 0x02 | u16 seq, u64 timestamp_us, u16 gain_q15 | 13 B |
| SYNC_PING | 0x03 | u64 t1_us | 9 B |
| SYNC_PONG | 0x04 | u64 t1_us, u64 t2_us, u64 t3_us | 25 B |

Characteristics: device info (read), alignment (write), gain stream
(write-without-response), sync (write + read).

## Develop

```bash
# Core DSP + protocol tests (no simulator or hardware needed)
cd mobile/core && npm install && npm test

# App (requires a dev build for BLE; Expo Go cannot scan)
cd mobile/app && npm install
npm run typecheck
npx expo run:android   # or run:ios
```

The Speakers screen defaults to **simulated speakers** so the whole
flow (scan → connect → clock sync → layout → alignment → orbit) runs
in a plain simulator; flip the switch off for real hardware.

## Known limitations (explicit)

- Speaker firmware implementing the GATT server is not in this repo;
  `engint/spatial_audio/ble_protocol.py` is the reference codec for it.
- Positions are entered manually; acoustic ranging (chirp time-of-flight
  via the phone mic) is a future integration.
- Clock sync is millisecond-class over BLE — sufficient for gain
  envelopes, insufficient for phase-coherent tricks; none are claimed.
- The Play screen ships one built-in demo trajectory (orbit); arbitrary
  trajectory streaming exists in `@sofinity/core` but has no UI yet.
